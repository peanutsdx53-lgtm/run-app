# Explore usability and consultation navigation — approved one-round change

- Base: main 7ae1bf4d26e760bacec03430c53010512aa830a8, Git tree c1b4e95f399531e32427fe44c2c790acb01268c5; prior published CI 23/23 passed. Change is limited to approved Explore text, note affordance, navigation and adjacent UI.
- User observation: redundant headings, a misleading consultation summary button, and duplicated reflection history labels. Inspection of both knowledge and observation templates and the app handler confirmed the old action opened a theme/category draft with a blank question and a clipboard button, rather than Consultation & Sharing.
- Functional design: use existing consultation route, no new report, no automatic text transfer or external sharing. Explicit selected manual record is checked through existing typed RecordRef validation; if absent, unselected or unreadable, leave the selector blank. Do not fall back to the latest record. Do not display an unrelated daily condition when no run is selected. Direct Home consultation behavior remains unchanged. Existing private opt-ins stay off. On return restore the exact originating route and selected topic/tool values using ephemeral memory; saved notes are re-read, not transferred. If consultation page is reloaded, transient context is lost safely; return to general Explore with no implicit record. No new persisted data or schema.
- Screen design: one shared final action section for all 27 themes (10 knowledge and 17 observation), one optional explanatory sentence and a distinct writing button, separated navigation link with chevron, single full-width Reflection Notes control with count. Preserve source/limitations disclosures, existing 500-character notes, note scope and revision behavior. Update both Japanese and English copy. No AI-generated images or external material. Remove only retired clipboard code and unused related phrases. Cache versions updated.
- Design rationale: Personal Informatics and lived-use framing already adopted in the approved theory motivate optional interpretation/reflection and later revisits, not a required response or an automated conclusion. Separating record facts, subjective observations, and user-selected sharing is a boundary condition of the existing design. The specific label/affordance changes are usability design judgments motivated by the user's direct observation; their effect on comprehension or self-understanding has not been measured. Scientific equations, research content, reference limits and formal Current unchanged.
- Local independent preflight: 886/886 Node tests, including four new tests for 27 topic action contracts, selection and return routing, private note/English handling, and ephemeral context. 1197 referenced dependencies, zero issues. Public terminology scan completed (existing internal scientific field names retained); git diff --check passed. Chromium component fixture imported 69 actual production modules with original styles and synthetic inputs. All 27 themes × 2 languages × 2 themes × 4 widths × 2 text sizes = 864 conditions; changed actions ≥44px, no horizontal page overflow, no remaining Japanese system text in changed English action/footer. Real production note rendering and save using in-memory test storage, preservation of Japanese authored note, and consultation mount tested in 6 conditions (JA/EN, selected/unselected/missing record), including no private default opt-in and no unrelated daily condition on opt-in without a chosen run. Observed actual screenshots of changed stage, history control, writing modal and unselected consultation. No JS page errors in fixture.
- Limitation: full local application navigation blocked by browser administrator policy. Fixture isolates actual modules/markup/CSS and does not establish full SPA hash-navigation, actual storage or WebKit success. Added real end-to-end navigation/privacy/return and reload assertions to existing dual-engine Explore CI; updated obsolete clipboard checks to assert equivalent privacy boundary after navigation. Require full candidate CI and screenshot inspection before main merge; public CI afterward. Real-device and subject validation remain outside scope. One approved change round; no plan expansion.
