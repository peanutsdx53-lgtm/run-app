# P14.5 履歴 GPS カード・バックアップ見出し・ホーム操作色の一括収束
日付: 2026-11-10
変更対象: RunLoad v2 の履歴／ホームの表示層のみ。本人データ、計算式、結果画面3タブ、研究理論は変更しない。

## 観察と根本原因
- 履歴本体は Shadow DOM 内の `.stage` が左右余白を管理する一方、外側の GPS カードは `.main-content` の全幅（width:100%）を使っていた。カード単体の max-width: none 指定は余白不一致を解消しない。
- バックアップ欄 summary は裸のテキストノードと小文字を横並びで可変幅にしており、320px 付近で語句の途中の予期しない折返しが起こりうる。
- ホームのコンディション／実績「開く」は形・文字は揃っているが背景色の設計原理が異なり、後者は実績カードと同系色で操作の分離が弱かった。

## 機能設計根拠
履歴の閲覧・展開、バックアップ・保存容量管理、コンディション／実績詳細を開く操作は維持する。カードは記録に基づく意味を伝えるが、装飾色は医学的・運動科学的評価指標を表さない。本人のデータや数式には触れない。

## 画面設計根拠と変更
1. GPS 外側カードは履歴本体の `.stage` と同一の左右余白（通常 clamp(15px,2.6vw,44px)、870px以下14px、540px以下12px）を使用する。1550px の中央寄せ最大幅も同一にし、1920px を含む大画面でも上の全面幅ヒーローカードと左右端を一致させる。
2. バックアップ見出しと補足を別要素にし、470px以下ではタイトル／補足の二段＋右端開閉記号にする。両句を途中で折返さない。
3. コンディション（紫）・実績（銅）の両方に共通の青系 Open バッジ（背景・境界線・文字）を設定。カードの違いは残し、操作は同色・同形・同サイズにする。

## 再発防止・受入条件
既存の Current 20 画面 Playwright 撮影（Chromium／WebKit、320／390／1440px）に実 DOM の GPS と履歴上部カードの左右座標一致、バックアップ2フレーズ非分割、モバイル二段、同一 Open ボタン色・非切断を追加。GPS の保存管理を実際に開いた状態もスクリーンショットへ記録する。静的テストで仕様トークン・アプリ実装の存在を確認する。既存状態・ナビゲーション・手入力保存の検査を残す。

## 検証の限界
CI のブラウザ画像・幾何検査は実機 iPhone のフォント設定、セーフエリア、WebKit の全条件を完全には代表しない。内部評価から自己理解への効果や健康上の改善を主張しない。
