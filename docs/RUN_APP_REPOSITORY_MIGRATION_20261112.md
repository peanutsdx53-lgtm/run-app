GitHub Actionsが多数登録された開発用リポジトリと、アプリの実装を継続するリポジトリを分離する。今後の最終配布先への移設に備え、ファイル完全性を照合できる手順を残す。

- 移設元: https://github.com/peanutsdx53-lgtm/runload-app-v2 の main / 固定コミット `1152d315f3cedddff8f5c86df01dd23bef8e6bb5`
- 移設先: https://github.com/peanutsdx53-lgtm/run-app の main
- 元リポジトリの削除・変更・履歴書換えは行っていない。
- **434ファイル**をパス・Git blob SHA一致で複製。アプリのHTML/JS/CSS、core、UI、PWA、JSON・画像・SVG、テスト181件、設計資料92件、READMEを含む。PNGはUTF-8に変換せずバイナリのまま複製。
- 意図的に除外: `.github/workflows/` の **56 YAML**。旧CIのジョブ滞留を新リポジトリへ持ち込まない。

## 機能設計上の維持事項
計算式、科学文献の参考値と適用条件、記録・GPS・同意データの形式、表示言語、結果3タブ、保存済みデータを編集する手順は変更しない。正式Currentも変更しない。移設はプログラムのコピーであり、自己理解の向上や29成立条件の実証ではない。

## 画面・PWAの維持事項
両manifestの `start_url` と `scope` は `./`、service workerは `./sw.js` / `./`を基準にしている。したがって新しいGitHub Pagesのサブパスで動作する構造だが、**公開URL設定や実機での起動は別途検証が必要**。旧リポジトリでインストールしたiPhoneのPWAが新URLへ自動的に切り替わるわけではない。

## 今後の実行・検証手順
1. 新リポジトリを取得し、`python3 -m http.server 8000` などで `index.html` を配信する（静的アプリ、ビルド不要）。
2. ローカルで `node --test tests/*.test.mjs` を実行する。ブラウザ受入はREADME記載のPlaywrightで別途実施する。
3. 新リポジトリのCIは**少数・変更対象のみ**の構成を別途設計し、旧56ワークフローを丸ごと追加しない。必要な統合監査は公開前のゲートにする。
4. GitHub Pagesを使う場合は新リポジトリの設定・実際の配信完了を確認し、そのURLでPC/iOSの初回起動・オフライン・翻訳・カード編集を再検証する。
5. 今後の移設ではコピー元をコミットSHAで固定し、ツリー内の全blob SHAとパスを比較する。欠落、相違、対象外のファイルがないことを機械的に確認する。

## 個人の記録についての注意
GitHubコードリポジトリへのコピーでは、利用者端末のlocalStorage/IndexedDBに保存された走行記録は移動**しない**。旧URLと新URLのブラウザ保存領域は別である。バックアップ／復元は本人の明示操作・安全な保存先・データ確認を前提にし、実記録を公開GitHubへアップロードしない。旧PWAを削除したりブラウザデータを消去したりしない。
