## 機能設計根拠 WHAT/WHY
- 天候・風・湿度は一時的なUI選択、`environmentNote`は本人の下書きテキスト、保存済み活動レコードは別の操作で成立する三つの意味。選択のみでメモに書き込まない。「今回の下書きに反映済み」を活動保存済みと表示してはいけない。
- 任意の気温0℃と空欄を区別。既存の`temperatureError`、500文字上限、明示的`applyEnvironmentSelections`、同一反映重複防止を保持。追加の天候・条件保存スキーマを作らない。
- 「反映せず戻る」は気温や本人の記述を消さず、一時選択だけを破棄。既存の未反映警告で本人の選択を要求する。手入力から開いた場合は手入力へ、保存前確認から開いた場合はその確認へ戻る。
- UX-028は5画面共通のフッターCSS・配置を変更しない。ROF-Jの0≠未回答、保存コースの操作、身体自覚メモの明示転記、走歩入力検証を守る。

## 画面設計根拠 HOW/WHY
- 環境の既存の状態表示に、一語のステータスラベル「選択なし」「一時選択・未反映」「今回の下書きに反映済み」を分けて配置。色だけでなく文字と`aria-live`で区別し、状態説明は短い既存文のまま。
- 環境メモ側の入力要約に「環境メモへの反映は走行記録の保存完了ではない」と短く記載。英語辞書には既存の動的状態文を含め明示的に対訳登録。本人の原文は自動翻訳しない。
- 5画面の戻るフッターは既存`ui/recordReturnActions.css`を使用。見た目の追加変更は行わず、実画像でJA/EN・幅・200%・状態・適用/破棄を確認する。
