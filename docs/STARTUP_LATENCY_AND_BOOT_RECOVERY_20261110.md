# 起動遅延・読み込み表示の改善記録（2026-11-10）

## 現状と分析の範囲
対象main: `a41665a9c326c1fd182d424c5d3a0f48c379f9b0`。起動前48個の動的モジュールを逐次await、25個のCSSファイルを読み込み、IndexedDBのGPS v1→GPS v2→手入力正本を逐次検査していた。GPS v1/v2はそれぞれ最大7秒、手入力正本は最大8秒の接続待ちを設定する。Service Workerはloadイベントで登録を開始し、208件のURLを事前キャッシュしていた。これはコード構造に基づく分析であり、実機で22秒の待ち時間を測定したという意味ではない。

## 機能設計の改善
1. 初期モジュールは同一の48ファイルを `Promise.all` にまとめて並列取得。画面が使うモジュールの種類や科学計算・保存形式・結果3タブは変更しない。速度が改善するかは通信状況に依存するため、短縮秒数はブラウザ検査で検討する。
2. 3つの独立したIndexedDB初期読み取りは `Promise.all` で並行する。GPS v2一覧の結果は従来どおり後続の保存・削除・フォーカス復帰時に再取得できる可変キャッシュとして保持する。手入力の正本確認が完了する前に記録を「記録なし」と表示しない。失敗時は既存の不正読取安全停止処理に従い、暗黙の修復や削除はしない。
3. 初回画面描画完了までService Workerの更新登録を始めず、事前キャッシュ通信が初回画面のモジュール取得を阻害しにくくする。バージョン付きJS/CSS/manifestは**現在のキャッシュだけ**から優先読取し、起動後の再訪時に通信待ちを避ける。未キャッシュの版・ナビゲーション・バージョン無しファイルは従来どおりネットワークを先に確認する。新旧アプリの混在を避けるためapp.js/pwa.js/SWの版は必ず同時に更新する。

## 画面設計の改善
- HTMLだけで描画できる濃紺・青緑系の軽量な起動画面。タイトル「走行記録と振り返り」。画面の準備段階は確定していないためパーセント進捗を示さない。
- 読み込みが4秒を超えたら「画面の準備を続けています」、12秒を超えたら通常より時間がかかっている旨と任意の「再読み込み」を表示。停止を偽る自動再読込をしない。
- モジュール読込失敗・JavaScript起動例外は「画面を開けませんでした」とリトライ案内へ切り替え、表示が永久に「読み込み中」に固着する問題を減らす。ユーザーの記録削除やローカル保存領域の初期化はしない。
- reduced-motion設定ではアニメーションなし、状態テキストはaria-liveで通知、操作ボタンは44px以上。
- 初回画面と起動処理の責務を分離し、動的な記録や疲労感の内容をローディング画面に表示しない。

## 受入と残余リスク
- Node静的契約テストとChromium/WebKit実画面で、遅延時の案内、起動エラー時の再試行、実際の初回ガイド表示、レイアウト、安全な保存の継続を確認する。現行のオフライン・保存・結果・全画面ブラウザ受入も実施する。
- 48件を同時取得するため、一部の低速端末・接続ではピーク通信が増える可能性は残る。実機実測・大量保存データ・移行後のPages配信は別の検証が必要。
- 初期CSSは本変更では維持（25枚の内訳を壊さないため）。後日の非ブロッキング読み込み・画面別分割は別の試験が必要。
